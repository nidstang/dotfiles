# Formato de MISSION.md
`MISSION.md` vive en la raíz del espacio de trabajo. Captura el _motivo_ por el que el usuario está aprendiendo este tema. Cada decisión de enseñanza — qué enseñar a continuación, qué recursos sacar a la luz, qué ejercicios diseñar — debe poder trazarse hasta este documento.
## Plantilla
```md
# Misión: {Tema}
## Por qué
{1-3 frases. El objetivo concreto del mundo real que el usuario está persiguiendo. ¿Qué cambia en su vida o en su trabajo cuando tenga esta habilidad? Evita encuadres abstractos como "para entender X" — empuja hacia el resultado subyacente.}
## El éxito tiene este aspecto
- {Una cosa específica y observable que el usuario podrá hacer}
- {Otra cosa específica}
- {…}
## Restricciones
- {Tiempo, presupuesto, compromisos previos, preferencias de aprendizaje, cualquier cosa que acote el enfoque}
## Fuera de alcance
- {Temas adyacentes que el usuario explícitamente no quiere perseguir ahora mismo — protege la zona de desarrollo próximo}
```
## Reglas
- **Una misión por espacio de trabajo.** Si el usuario quiere aprender dos cosas no relacionadas, son dos espacios de trabajo.
- **Concreto antes que abstracto.** "Correr una media maratón en octubre" gana a "ponerme en forma". "Sacar una CLI en Rust para mi equipo" gana a "aprender Rust".
- **Empuja contra la vaguedad.** Si el usuario no puede articular el porqué, entrevístalo antes de escribir nada. Una mala misión es peor que ninguna misión.
- **Revísala cuando la realidad cambie.** Las misiones cambian. Cuando el objetivo del usuario se mueva, actualiza este fichero — no dejes una misión obsoleta guiando sesiones futuras.
- **Mantenla corta.** Si `MISSION.md` se pasa de una pantalla, ha dejado de ser una brújula y ha empezado a ser un plan.
